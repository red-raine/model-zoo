single benchmark**. Its "decontamination" was a docstring promise over a length + code-shape

## What was done

1. **Diagnosed the failure chain.** `simple_decontam.py` reads `spine_train.jsonl`, writes
   `spine_train_clean.jsonl`; the clean file was then copied **over** the input. Both ended
   byte-identical (`E2947078…`). Also found: `validate_passes.py:395` P0 decontamination is a
   literal `pass` **and** `hasattr(decon,"MINHASH")` is always False (constant is
   `MINHASH_THRESHOLD`) — a double no-op; `recipe.py`'s `decontam_refs:
   [mmlu,arc,hellaswag,winogrande]` has zero consumers.

2. **Proved `decontaminate.py` cannot help prose.** `extract_assistant_code()` falls through
   to the whole text, so layer 4 is skipped (`if user_text:` is False without ChatML) and it
   returns `CLEAN, 0 flagged` **without evaluating anything** — a vacuous pass.

3. **Recovered the lost corpus, exactly.** `pipeline.py balance --target-rows 20000
   --eval-frac 0.02` (seed 42) → 19,592 train + 408 eval, and `spine_eval.jsonl` came back
   **byte-identical** (`4B3A1737F141BE17`). Proof the regeneration is faithful.

4. **Built `tools/data/refs_vault.py`** → 40,303 entries, sha256 `a02530625c52fb06…`:
   gsm8k 8,792 · mmlu 14,042 · hellaswag 10,042 · arc 3,548 · winogrande 1,267 ·
   truthfulqa 817 · mbpp 1,631 · humaneval 164.

5. **Built `tools/data/decontam_text.py`** — 13-gram (primary) + 8-gram (warn) + MinHash +
   exact + prompt-leak. Works on `text`, `messages`, `prompt`/`completion`, `instruction`,
   `code`. Handles 400 KB rows (sliding window over the whole document).

6. **Built `tools/data/gate.py`** — the contract. `guard(data_path)` raises unless a sibling
   `*.gate.json` says `verdict=CLEAN` **and** `decontam_self_test` is `n/n`. Called inside
   `tools/tm/train_arc.py` **before `import torch`**, so the wrapper is not the chokepoint.
   Also does local MinHashLSH dedup and the eval-overlap guard.

7. **Built `tools/data/license_gate.py` (G-LIC)** — resolves licence via overrides →
   `sources.py` → local LICENSE files → HF API. Tags `license` + `commercial` on every row.

8. **Built `tools/data/pii_gate.py` (G-PII)** — dependency-free scanner (no presidio):
   credentials, PEM, JWT, cards (Luhn), phone, email, IP, IBAN, TCKN. Redacts by default.

9. **Built `tools/data/archive_ledger.py`** — two-phase verified archive with a sha256 tree
   fingerprint ledger and `restore`. **3.32 GB** moved; round-trip tested.

## The two bugs the self-tests caught in my own code

**decontam_text.py** — the rolling hash subtracted the outgoing term *after* multiplying
instead of before, so the accumulator carried the whole prefix instead of the sliding window.
Verbatim copies still matched, so a naive test would have passed. Only the **20-word
mid-document slice** fixture exposed it:

```
[FAIL] gsm8k_20word_slice  expected=CONTAMINATED  got=CLEAN
```

**pii_gate.py** — flagged 3 "secrets" that were all placeholders (`your_client_id`,
`your_api_key`, `AKIAIOSFODNN7EXAMPLE`). Added a severity-aware placeholder filter. Then
over-suppressed: the entropy floor killed every phone number (inherently low-entropy) and
`example.com`. Made suppression severity-aware — **secrets** get the entropy floor, **PII**
does not. Also tightened the card regex: `(?:\d[ \-]?){13,16}` accepted a space between
*every* digit, so a citation range (`Berleant [1985 … 2013]`) became a Luhn-valid 16-digit
card.

**archive_ledger.py** — `_row_is_empty()` returned `not d`, so a dict of empty strings scored
as *non-empty* and 2M empty rows passed verification.

## A claim I refuted

The prior audit said `fenrir_v2_1` was "6 × 99,870 empty rows". Measured: **199,740 distinct
rows**, 50% empty / 50% real — **0.68 GB of genuine cybersecurity data**. We were one
`apply` away from archiving it. Empty-shard verification now requires *empty AND degenerate*.
